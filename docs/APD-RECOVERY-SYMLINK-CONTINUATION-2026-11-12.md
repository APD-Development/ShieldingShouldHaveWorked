## Bounded source defect and code

`StatsStore.recoverAll` selected `runs/*.apdlog` entries by `File.isFile()`, which follows filesystem symlinks. It then invoked `LogRecovery.repair`, which intentionally backs up damaged tails and truncates damaged log files. Thus a symlink in runs/ could cause destructive truncation of an external log target. This is a concrete source-level boundary gap, **not** a claimed actual owner-device incident. It differs from the previously fixed archive temporary and destination symlink paths.

- Production commit [`f30dcbc5`](https://github.com/APD-Development/ShieldingShouldHaveWorked/commit/f30dcbc56878d399d4dac5427fe37df2d38f30b1) canonicalizes each candidate log before destructive repair and accepts it only when its canonical parent is the designated canonical runs directory and its filename remains identical. Ordinary symlinked configured storage roots remain compatible; per-log aliases/escapes are excluded from destructive repair. All existing legitimate local log repair and damage-tail preservation remains unchanged.
- Regression commit [`642a1d4a`](https://github.com/APD-Development/ShieldingShouldHaveWorked/commit/642a1d4a4ae5286890496ca46cf090c56650a1d1) adds `recoveryNeverTruncatesSymlinkedRunLogs`: a real truncated run log outside runs/ linked into it, another linked alias to a legitimate local run, real local damaged-log repair, original outside bytes, sidecar names and index preservation.
- Exact source gate commit [`d7ea025a`](https://github.com/APD-Development/ShieldingShouldHaveWorked/commit/d7ea025a97f9adc9d9e9cdfa6968b5ff9b91ef90) runs complete Gradle core tests, desktop/Android debug/release/instrumentation Java compilation, >=3,319 tests and zero failures/errors/skips, plus the new and existing repair regression.
