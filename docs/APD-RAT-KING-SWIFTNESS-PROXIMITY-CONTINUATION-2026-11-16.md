## Evidenced performance issue and bounded change
- Previously `RatKingQuickSearch.speed` called `enemyNear(level,cell)` for every priced route step when Swiftness is active. Every call allocated a floor-sized `int[]`, initialized the full array, allocated a queue, and ran a radius-three path search that examined all enemies at each reached position. The route-pricing Dijkstra algorithm can price many such steps per quote. This is redundant work on static floor topology and enemy positions during pure pricing.
